# 普通委员可提交增删，完整名单仅安全员可读

## 2026-10-20 用户确认

日常报名和晚餐资格的录入／移除不依赖开发者 super 权限。普通 committee 可以按自己掌握的姓名、邮箱等资料提交新增或按邮箱移除，但不能查看已有名单；authorised 安全员可以查看完整名单并直接维护。本决定替代先前额外要求账号管理能力才能维护晚餐名册的解释，也纠正原有 Registrations 对普通成员全面拒绝的实现。

此次不改账号管理或角色存储，不新增第四种业务角色，不把 canManageAccounts 当作日常名单维护门槛。继续使用 Issue #102、分支 codex/102-match-dinner-check-ins 和 PR #103；未合并，不包含 QR 权限 PR #101 的实现。

| 能力 | committee | authorised 安全员 | 是否必须依赖 super |
|---|---|---|---|
| 按邮箱提交报名新增／取消 | 允许，不返回名单 | 允许，可查看结果 | 否 |
| 按邮箱提交晚餐资格新增／恢复／停用 | 允许，不返回名单 | 允许，可查看结果 | 否 |
| 查看报名及通用资格完整名单 | 拒绝 | 允许 | 否 |
| 本场晚餐核验、发放与确认清除误勾 | 允许 | 允许 | 否 |

报名的移除沿用 Cancelled 状态；晚餐资格的移除沿用失活。均保留历史，不级联删除身份、签到或已发放记录。委员会新增报名仍不是确认签到，参与者扫码提交才可自行签到。

## 实现与隐私边界

普通成员访问 Registrations／Dinner eligibility roster 时看到专用提交表单，没有记录列表、搜索、既有姓名、邮箱、学号、预填值或存在性结果。已有敏感读取服务仍要求 authorised。普通成员入口在读取名单之前分支，根本不调用名单读取函数；不是把完整数据传给浏览器后隐藏。

新增 submit_member_list_change RPC，仅 authenticated 可执行，使用真实 auth.uid 并检查活跃后台资料，SECURITY DEFINER 固定空 search_path。输入限定列表类型、操作、邮箱、姓名、学号与活动，不接受操作者或任意表名，返回 void。新增、重复、已有／不存在的移除统一确认，不返回已有身份、重复状态或行数。对既有参与者身份不符的提交不改写身份，也返回同样确认；录错资料应由安全员核对。

写入按标准化邮箱串行化；同邮箱晚餐新增只恢复资格，不以普通成员提交的名字覆盖已有名字。报名按活动／参与者唯一约束写入，可由工作人员明确恢复取消的报名；不产生签到。只在实际有报名／资格时执行取消／停用，既有发放历史不隐藏。

完整表级 RLS 继续拒绝 committee 的参与者、报名和通用名册读取。安全员的晚餐表写策略从额外账号管理条件改为 authorised；服务器 save／remove 同样移除该额外门槛。安全员可用完整列表和直接维护控件，普通成员只能通过窄写接口。

## 部署和回退

先应用 `20261020014659_allow_committee_blind_registration_and_dinner_writes.sql`，再发布／重建前端；此前迁移须按时间顺序已应用。已有库禁止 reset，镜像重建不会自动执行迁移。生成类型由 Supabase CLI 更新，新增函数签名随代码提交。

新迁移不新增表、外键、索引或约束，复用原有唯一性、审计和软移除状态。无需回填，原报名／签到／资格／发放均保留。

回退先撤下提交表单，再通过前向 migration 撤销新 RPC execute 并恢复此前安全员写策略／服务器边界；保留已经提交的记录和取消／失活事实。不能为回退删除资料或伪造状态恢复。回退会重新引入普通成员无法维护的限制，需业务负责人决定。
