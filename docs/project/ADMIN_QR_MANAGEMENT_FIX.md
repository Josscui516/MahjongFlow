# 管理员二维码权限修复

2026-10-16 用户确认管理员应能生成二维码，并报告队友在 Docker 中看到“没有生成权限”。本次修复对应 [#99](https://github.com/Josscui516/MahjongFlow/issues/99) 的二维码管理后续缺陷，沿用已授权的单个补丁 PR → `main` 交付例外。

## 已复现的缺陷与修正

`can_manage_accounts` 是独立管理员能力，合法账号可以同时为 `committee`。旧二维码入口与数据库管理函数只接受 `authorised`，因此这类活跃管理员无法读取设置、保存报名时间、生成或撤销链接。此前浏览器走查使用的是同时具有 `authorised` 角色的管理员，未覆盖这个组合。

二维码管理现在接受“活跃管理员或活跃 authorised 人员”，并在入口、服务端 guard 及四个仅授予 service_role 的 RPC 中保持一致。普通委员、停用用户和匿名用户继续拒绝。浏览器仍不能直接调用这些 RPC 或伪造操作者；操作者来自服务端真实会话。本次没有把管理员能力等同于参与者数据访问角色：committee 管理员的报名、签到和晚餐明细权限不扩大。

旧 RPC 也把已完成／已取消活动或缺少报名窗口报告为 `42501`，导致前端误显示权限不足。现在仅真正权限不足使用该错误；活动状态、窗口缺失、记录不存在分别返回 `PQR01`、`PQR02`、`P0002`，映射为明确的界面反馈。非 Scheduled 活动页面不显示生成按钮，说明限制来自活动状态。

本补丁同时纳入已在本机复现的独立问题：本地 production build 使用 loopback 配置和已确认的本机 Host 时，允许生成 LAN 地址；正式 HTTPS origin 保持可信配置，Docker 仍需显式宿主机地址，避免生成容器地址。这不是对队友 Docker 失败原因的替代推断。

## 部署与回退

先在目标环境应用 `20261015231742_fix_admin_qr_management_permissions.sql`，再发布／重建前端。只拉取 Git 代码或只重建 Docker，不会自动升级已有数据库中的函数。不要用 reset 更新已有数据库。迁移只替换函数及 execute grants，不改账号角色、不改表数据，也不撤销现有二维码。

迁移保持函数签名不变，数据库类型已重新生成核对，无类型差异。回退前端时可保留此迁移；若要回退数据库函数，应通过前向迁移恢复上一版本四个管理函数及原 service_role-only grants，但会重新引入独立管理员被拒绝的问题，需单独评估。
