# 扫码注册与工作人员确认到场分离

## 当前决定

2026-10-21，用户明确调整公开二维码流程：扫码填写资料只创建活动注册，必须由 authorised 工作人员手动确认到场。此决定替代 [2026-10-20 扫码自动签到](QR_SELF_CHECK_IN_CORRECTION.md)。对应现有 US-05，不新增角色或个人信息字段。

公开表单及结果页使用 registration 文案，二维码管理标题为 QR registration。首次和重复注册均提示请工作人员确认到场。Currently registered 统计有效注册，Confirmed attendance 仍统计 confirmed 签到，不能互相推算。全新活动首次注册应为 1 / 0，工作人员确认后为 1 / 1；两个总数最终可以相等。

## 实现与权限

- 应用公开入口调用原有 `submit_event_registration`；旧 `submit_event_self_check_in` 通过新增迁移变成仅注册兼容入口，旧应用或旧二维码也不能自动确认到场。
- 注册仍校验 token、Sydney 开放窗口、姓名与邮箱、隐私同意，并保留重复提交幂等及工作人员取消保护。扫码不创建、恢复或更新签到。
- 工作人员使用现有 Manual attendance 入口；原服务端鉴权、RLS、可信操作者及手动来源记录保持有效。普通 committee 与匿名会话不能写入签到，匿名也不能直接调用特权注册 RPC。
- 晚餐领取仍要求有效注册、工作人员确认到场和活跃通用资格名册匹配；单独注册不会获得领取资格。

## 部署、数据与回退

先应用 `20261021123653_separate_public_registration_from_staff_attendance.sql`，再发布应用。迁移只替换旧 RPC 的函数体、执行模式和说明，未新增表、外键、唯一约束、检查约束、索引或 RLS；仅 service_role 可执行旧 RPC。生成类型须通过 CLI 重新生成，函数签名保持兼容。

已有注册和签到全部保留，不批量删除历史二维码签到，也不伪造工作人员确认。已有演示活动的两个总数可能继续相同。虚构 seed 不需要改写；新注册不再自动产生签到。

回退须经业务确认，通过新的前向迁移恢复旧函数定义，再发布旧应用；不能修改已执行迁移或删除已有注册、签到及晚餐发放记录。回退会重新启用自动签到，需明确告知工作人员。

## 验证范围

SQL 回归覆盖两个公开 RPC 仅注册、重复、身份不符、同意、无效 token、工作人员手动确认、取消及撤销保护、晚餐匹配和 committee／匿名拒绝。应用回归与浏览器验证覆盖首次注册、重复注册、1 / 0 聚合及工作人员操作后的 1 / 1。浏览器与数据库测试只使用独立虚构资料并清理。

本次结果：新 SQL 回归 23 项通过；相关应用测试 369 项通过、8 项默认跳过的本地晚餐数据库测试另外启用后全部通过；lint、类型检查、生产构建及数据库 schema lint 通过。Chrome 实际提交后读到注册 1／签到 0，authorised 工作人员手动确认后读到 1／1，重复注册不增加记录，工作人员来源为 Manual。旧全量 SQL 测试未全通过：其中依赖 `40000000-...` 历史 seed 活动的 token 权限测试因本地缺少该 fixture 无法启动，本次不对现有数据库 reset 或补入历史 seed；不将此结果记为全量通过。
