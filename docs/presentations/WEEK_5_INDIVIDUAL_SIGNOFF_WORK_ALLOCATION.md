# Week 5 Individual Group Member Sign-off 工作分配

> 适用项目：MahjongFlow
>
> 团队：S1_CS_01
>
> 用途：组织 Week 5 plain-text slide deck 签核准备
>
> 边界：本文只分配工作、规定证据和检查标准，不代替任何成员撰写其演讲内容。

## 1. 本次签核目标

团队需要准备一份纯文本幻灯片草稿，让 teaching staff 能够确认：

1. 标题页包含项目名称、组号、项目主题，以及全部成员在 Allocate+ 中登记的姓名和学号；
2. Topic Overview 明确列出每名成员的演讲贡献；
3. 每张后续内容页明确标注演讲者；
4. 每张内容页由对应演讲者本人提供 3–5 个 bullet points；
5. 全组内容覆盖项目方法、过程追踪、里程碑、当前问题、风险、未来问题、角色与任务分配、用户参与和需求验证；
6. 所有进度陈述都能由仓库、GitHub、Risk Register、SMART Goals、RTM、Kanban 或真实 stakeholder 记录支持。

本次工作不要求先完成视觉设计、动画或逐字演讲稿。签核前优先保证主题完整、事实准确、个人贡献清楚。

## 2. 统一交付格式

每名成员必须独立提交以下材料：

- 2 张本人负责的内容页；
- 每张内容页 3–5 个完整但简洁的英文 bullet points；
- 每张内容页至少 1 项可核查证据，例如 Issue、PR、测试结果、计划文档、RTM 条目、Risk Register 条目或 stakeholder 反馈；
- 每张内容页建议使用的 1 个视觉材料，例如截图、流程图、里程碑图、风险矩阵或 Kanban 摘要；
- 3 个可能被 teaching staff 提问的问题，以及本人能够解释的回答要点；
- 自己在 Allocate+ 中登记的准确姓名和学号；
- 1 句可用于团队结论页的“为什么项目应继续获得 go-ahead”陈述。

成员提交的是内容，不需要自行统一字体、配色或版式。整合人只能压缩重复、修正格式和协调时间；涉及事实、观点或个人贡献的实质修改必须退回原作者确认。

## 5. 证据与事实规则

每个 bullet point 应尽量包含以下三层中的至少两层：

```text
事实或决定 → 可核查证据 → 对项目进度／风险／用户价值的意义
```

例如，成员不能只写 “We use Agile”。应说明团队具体采用了哪些 Sprint 机制、解决了什么协作问题，以及由哪份计划或 Project 记录证明。

统一事实规则：

- GitHub／Git 的实际状态优先于过期的 README 摘要；
- “已完成”必须有 merge、验收或测试证据；
- “已验证用户需求”必须有真实用户或 stakeholder 证据；
- roadmap 项只能称为 planned、next 或 not yet started，不能称为 delivered；
- 幻灯片、截图和演示只使用虚构或匿名化数据；
- 不展示密钥、真实账号、真实参与者资料或未脱敏日志。
