## 1. 评审目的

本次是项目开发期唯一一次 Stakeholder 阶段评审。目标是确认“会议 → 决策／讨论点 → 任务 → 返回来源会议”的核心工作方式是否符合委员会实际需要，并区分：

- 对既有 P0 场景 C-01 至 C-07 的澄清；
- 不改变范围的文案或演示反馈；
- 应进入 Post-MVP Backlog 的新增能力；
- 必须由团队正式批准并同步权威文档的范围替换。

评审不能现场扩展 Sprint 4，也不能把未通过内部门禁的功能展示为已验收。

## 3. 演示脚本

1. 使用虚构委员会账号打开虚构会议详情；
2. 从关键决策选择“创建任务”，确认表单展示不可编辑的会议与决策来源；
3. 填写标题、描述、一个负责人、截止日期和允许状态并提交；
4. 打开任务详情，确认字段持久化并可返回来源会议；
5. 返回会议，确认关联任务列表可以重新打开该任务；
6. 从讨论点重复流程，确认 decision 为空且 discussion source 被保留；
7. 演示缺少负责人／截止日期、重复提交、missing source 和匿名直接访问的安全反馈；
8. 只口头说明下一阶段 Dashboard 方向，不展示或承诺尚未实现的临期、逾期、筛选或提醒。

## 4. 观察问题

1. 从决策或讨论点创建任务是否符合委员会实际记录行动项的顺序？
2. 来源上下文是否足以理解任务为什么存在？
3. 单一负责人、截止日期和三种状态是否足够完成 MVP 跟进？
4. 会议与任务之间的双向导航是否清楚？
5. 哪些建议只是对现有 P0 的澄清，哪些属于新能力？
