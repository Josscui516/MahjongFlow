## 1. 执行结论

已对 11 个实体的全部字段、Supabase Auth 外部数据、token 页面临时输入、派生
结果、聚合返回值和日志数据完成用途、隐私级别、读写角色、必填性、最小化
理由及生命周期审计。

结论如下：

- 数据库业务表不向互联网提供匿名 SELECT；
- 有效 token 页面只披露活动名称、时间、地点、窗口状态和是否要求学号，不
  返回活动描述、内部状态、名单或参与者资料；
- `full_name`、`email`、参与记录和个人资格为敏感数据；`student_id`、密码、
  会话秘密、server secret、明文签到 token 和 token 摘要为高度敏感数据；
- 普通委员会只能读取不含个人字段的活动报名数和签到数；
- 没有 P0 用途的个人字段继续排除，不进入 schema、表单、日志、seed、截图或
  API DTO；
- 开发、测试和演示只允许确定为虚构或匿名化的数据；生产数据不得复制到这些
  环境；
- Stakeholder 尚未批准生产保留期限，因此本文只定义用途结束和清理触发条件，
  不承诺永久保存，也不虚构具体天数。

## 2. 隐私级别定义

| 级别 | 定义 | 默认访问原则 |
|---|---|---|
| 公开 | 可在完成指定入口校验后向当前外部用户披露的最小非个人活动信息 | 仅有效 token 的当前活动上下文；不是匿名数据库公开 |
| 内部 | 委员会协调、关系和审计信息，不应对活动参与者或互联网公开 | `committee` 与 `authorised` 按业务用途读取 |
| 敏感 | 可识别个人、揭示报名／出席／责任或推断个人行为的数据 | 参与者数据仅 `authorised`；内部责任字段仅相关后台用户 |
| 高度敏感 | 可用于身份冒用、越权访问，或属于强识别机构标识的数据 | server-only 或 `authorised` 最小用途；禁止进入普通响应和日志 |

有效 token 不是公开数据库角色。标记为“公开”的活动字段仍通过服务端
`get_check_in_context` 返回，`anon` 对 `events` 没有 SELECT policy。

## 3. 访问角色标记

| 标记 | 含义 |
|---|---|
| `T` | 持有效 token 的活动参与者，只通过 PG-03 服务端返回／提交 |
| `C` | 普通 committee 用户 |
| `A` | authorised 用户，包含秘书能力 |
| `S` | 系统／数据库／server-only 窄函数 |
| `M` | 受控维护人员或流程，不是普通应用页面 |
| `—` | 不允许 |

“写入者”是最终可信写入主体。用户通过表单提供内容时，服务端仍负责规范化、
会话归属和审计字段，客户端不能直接覆盖系统字段。

## 4. `profiles` 字段清单

| 字段 | 用途 | 级别 | 必填 | 可读角色 | 可写角色／来源 | 最小化与生命周期 |
|---|---|---|---:|---|---|---|
| `id` | 对齐 Auth 用户；负责人、创建者和修正者引用 | 内部 | 是 | C, A, S | S/M | 只用随机 UUID，不复制认证凭据；账号停用后在责任关系需要期间保留 |

| `committee_role` | 区分 committee 与 authorised | 敏感 | 是 | C, A, S | M | 只存两级能力，不保存职位履历；角色变更后立即更新并失效旧权限缓存 |

Auth 邮箱、密码散列、refresh/access token 和会话由 Supabase Auth 管理，不复制到
`profiles`。密码、会话和 server secret 属于高度敏感，但不属于业务字段。

### 4.1 Supabase Auth 与服务端配置边界

| 外部数据／秘密 | 用途 | 级别 | 可见范围 | 最小化与生命周期 |
|---|---|---|---|---|
| Auth 用户 ID | 将登录身份映射到 profile | 内部 | 当前用户、S；后台目录只见 profile ID | 与 profile 对齐，不建立第二个身份编号 |
| Auth email | 后台登录和账号恢复 | 敏感 | 本人、Supabase Auth、M | 不复制到业务表，不用于参与者匹配或营销 |
| 密码散列／认证 provider secret | 验证后台身份 | 高度敏感 | Supabase Auth | 应用、日志和维护文档均不可读取或保存明文 |
| access／refresh token、session cookie | 维持当前后台会话 | 高度敏感 | 本人安全客户端、Auth、可信服务端 | 使用安全 cookie／会话机制；失效后不可进入日志或数据库业务表 |
| publishable key | 初始化受 RLS 限制的客户端 | 公开配置 | 浏览器可见 | 不赋予敏感表权限；不能被误称为 secret |
| server secret／旧 service-role key | server-only 窄 RPC 与受控维护 | 高度敏感 | S | 绕过 RLS；不得进入浏览器、仓库、日志、截图或聊天；泄漏必须立即轮换 |

P0 不启用不需要的第三方身份 provider，也不从 Auth metadata 复制头像、电话、
生日或其他 profile 字段。

| `checked_in_at` | 实际签到时刻和资格依据 | 敏感 | 是 | A, S | S | T 只见当前请求成功，不返回持久化时间 |
| `check_in_method` | QR／Manual 来源 | 敏感 | 是 | A, S | S | T/C 不得读取个人方式 |
| `attendance_status` | 当前 confirmed／voided 状态 | 敏感 | 是 | A, S | A 经服务端；QR 仅创建 confirmed | T 的重复响应不透露具体状态 |
| `recorded_by` | 人工补签／更正责任 | 敏感 | 条件 | A, S | S（当前 A） | 未经人工处理的 QR 可空；不向 C/T 返回 |
| `created_at` | 记录建立时间 | 敏感 | 是 | A, S | S | 随签到记录 |
| `updated_at` | 最近人工更正时间 | 敏感 | 是 | A, S | S | 随签到记录；不保存完整审计日志 |

签到明细揭示个人出席，全部按敏感数据处理。普通委员会即使能看到活动，也
不能通过网络响应、缓存、日志或错误读取上述组成字段。

## 11. 临时输入、派生结果和聚合字段

### 11.1 PG-03 临时输入与输出

| 数据 | 用途 | 级别 | 是否持久化 | 可见范围 | 最小化规则 |
|---|---|---|---:|---|---|
| 完整 URL token | 当前活动入口能力凭证 | 高度敏感 | 否；只保存摘要 | T 浏览器当前 URL、S | 不记录日志、分析、错误或截图；撤销后失效 |
| 提交 email | 匹配当前活动已报名参与者 | 敏感 | 不作为请求副本持久化 | T 提交自己的值、S 处理 | 只在请求内规范化比较；不回显库内 email |
| 提交 student ID | 活动要求时辅助身份匹配 | 高度敏感 | 不作为请求副本持久化 | T 提交自己的值、S 处理 | `requires_student_id=false` 时不显示、不接受、不处理 |
| 活动名称／时间／地点 | 说明当前签到对象 | 公开 | 来自 events | 当前有效 token | 只返回当前活动，不支持枚举 |
| 窗口状态 | 告知 Open／Not open／Expired／Unavailable | 公开 | 否，实时派生 | 当前 token | 不返回原始 token 状态或内部 event status |
| `student_id_required` | 决定是否显示学号输入 | 公开 | 否，来自 boolean | 当前有效 token | 只返回 true／false，不返回任何已有学号 |
| 签到结果类别 | 告知当前请求 success／already processed／unavailable | 公开 | 不单独持久化 | 当前请求 | 不包含参与者 ID、资格、历史或失败细节 |

### 11.2 派生与聚合结果

| 结果 | 输入 | 级别 | 可读角色 | 是否持久化 | 隐私限制 |
|---|---|---|---|---:|---|
| Overdue／Due soon | 任务日期和状态 | 内部 | C, A | 否 | 不涉及活动参与者 |
| 本人任务 | assignee 与状态 | 敏感 | 当前后台用户；A/C 按共享任务权限 | 否 | “本人”按 auth.uid 计算，不暴露外部参与者 |
| 决策／讨论点已转任务 | 来源任务存在性 | 内部 | C, A | 否 | 不建立可写标记 |
| 活动筹备进度 | 关联任务状态 | 内部 | C, A | 否 | 只返回完成数／总数 |
| 报名人数 | registered 行数 | 内部聚合 | C, A | 否 | 只返回 event_id + count；无个人字段 |
| 签到人数 | confirmed 行数 | 内部聚合 | C, A | 否 | 只返回 event_id + count；无个人字段 |
| 个人晚餐资格 | 当前活动 confirmed 签到 | 敏感 | A | 否 | C/T 禁止；不建立资格字段或表 |

## 12. 聚合查询隐私审计

### 12.1 允许的 committee 返回合同

```text
event_id
registration_count
attendance_count
```

三个字段之外的键一律视为测试失败。聚合函数必须在数据库内完成计数后再返回，
不能先向服务端或浏览器读取个人行再求和。

### 12.2 禁止的聚合行为

- 返回或嵌套 `participant_id`、姓名、email、student ID；
- 返回报名／签到时间、状态明细、方式、记录人或更新时间；
- 返回个人晚餐资格、符合资格者数量或可逐步推断个人的搜索提示；
- 接受 email、student ID、participant ID 作为 committee 聚合筛选参数；
- 在错误、debug payload、cache key、analytics 或日志中附带组成行；
- 创建让 committee 可 SELECT 敏感底表的 view；
- 以“前端不渲染”为理由向浏览器传输隐藏字段。

### 12.3 验证要求

1. 使用 committee JWT 调用聚合 RPC，断言 JSON key 精确等于允许合同；
2. 用相同 JWT 直接查询 participants／registrations／attendance，断言 RLS 无行；
3. 请求不存在和无权活动，断言响应不暴露敏感行是否存在；
4. 检查浏览器网络、缓存和服务器日志不存在个人字段；
5. 使用 authorised JWT 验证明细端点与聚合端点分离。

## 13. 开发、测试与演示环境数据规则

| 数据类别 | 允许形式 | 禁止形式 |
|---|---|---|
| 后台账号 | 专用开发 Auth 用户、虚构显示名、无效示例地址 | 真实成员个人账号、真实密码、生产 session |
| 参与者姓名 | 明显虚构且不对应真实成员的名称 | 真实姓名、仅部分遮盖仍可识别的姓名 |
| Email | 保留域名，如 `person01@example.test`；Auth 必要时使用明确虚构的示例域 | 真实个人／学校邮箱、从生产复制的散列或变体 |
| Student ID | 明显虚构值，如 `TEST-0001` | 真实、截断、打乱或可逆转换的学号 |
| 会议／任务／活动 | 虚构标题、地点和内容；避免映射真实敏感事件 | 真实会议纪要、真实报名／签到或未公开活动资料 |
| 报名／签到／资格 | 由虚构参与者组合生成的成功、重复、取消、void 场景 | 生产导出、真实出席状态、真实资格截图 |
| Token | 测试运行时生成并在结束后撤销／清理 | 写入 seed、文档、fixture、截图或 commit 的可用 token |
| 日志／截图／录屏 | correlation ID 和虚构资料；展示前人工检查 | secret、完整 token、真实 PII、生产 URL 中的能力凭证 |

### 13.1 环境隔离

- 不从生产复制数据库 dump、Auth 用户、日志、备份或截图到开发／测试／演示；
- seed 文件只能包含虚构静态资料，token 和审计时间在运行时生成；
- 自动化测试结束后清理目标测试活动的报名、签到和 token，不使用广泛删除；
- 演示截图和录屏只使用专用虚构活动，并在分享前检查浏览器地址栏和网络面板；
- 如测试缺陷需要真实形状的数据，只复制字段结构和分布特征，不复制或可逆
  变换真实值。

## 14. 数据生命周期与清理触发条件

| 数据类别 | 何时需要 | 用途结束／清理方向 | 当前决定状态 |
|---|---|---|---|
| profiles | 后台账号有效或仍被责任字段引用 | 先停用访问；引用需要结束并按批准流程重分配／保留后再处理 | P0 可执行；不提供删除页面 |
| 会议／任务／活动 | 委员会协调和历史追踪 | 不因列表过期自动删除；未来归档不得断开来源 | 当前保留业务历史，不承诺永久 |
| participant 基础资料 | 活动身份匹配、报名／签到保留期内关系 | 无任何需保留关系且批准期限满足后清理主记录 | 具体期限待 Stakeholder |
| student ID | 至少一个相关活动确需证明 | 相关证明用途和批准期限结束后优先设为 NULL；不得因普通活动继续保留 | 具体期限待 Stakeholder |
| registrations | 报名管理、统计和活动后核对 | 按目标活动和批准期限清理；取消状态不等于立即删除 | 具体期限待 Stakeholder |
| attendance | 到场核对、人工更正和资格推导 | 按目标活动和批准期限清理；void 不等于立即删除 | 具体期限待 Stakeholder |
| token 摘要／元数据 | 当前入口验证、撤销和最小安全审计 | 活动结束先撤销；用途和批准期限结束后随目标活动安全清理 | 清理流程步骤 7 规划 |
| 临时 token／身份输入 | 当前请求处理 | 响应结束即丢弃，不进入日志或持久请求副本 | 已确定 |
| 安全日志 | 故障定位与滥用检测 | 只保留最短必要周期且无原始 PII／token；具体周期由部署政策批准 | 具体期限待 Stakeholder／团队 |

在期限批准前，系统不得在隐私说明中写“永久保存”或虚构删除天数。最终上线
前必须把批准期限转换为可执行清理任务、验证和用户说明。

## 17. 对步骤 5 的一致性修正

加入这一布尔值。它不包含个人数据，也不允许读取任何已有 student ID。

其他权限边界无需变更。
