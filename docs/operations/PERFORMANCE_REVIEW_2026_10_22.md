# 本地前端性能检查与优化（2026-10-22）

## 证据与原因

运行中的 `mahjongflow-frontend` 原命令为 `next dev --webpack`，`src`、`public` 从 Windows 只读挂载。日志中首次访问活动详情达到 7.5 秒（框架 4.1 秒、应用 3.3 秒）；Dashboard 曾为 2.4 秒（框架 1.921 秒）。这些是历史单次记录，不是统计基准。日志还存在 `Unexpected end of JSON input`；未复现其原因，不能将其归因于业务查询。

已检查所有 `src/app/**/page.tsx` 的入口、数据依赖及布局权限调用。开发模式按需编译影响全站；布局、页面和各服务重复验证权限增加数据库往返。Dashboard 的 unfinished、dueSoon、overdue 原本重复读取同一组任务。

## 本轮变更

- 共用权限入口使用 React `cache`，仅在同一次服务端渲染共享结果，不跨用户或请求缓存，不删除任何角色检查。
- 每次 Dashboard 创建独立查询适配器，共享相同状态／负责人对应的分页 Promise；普通单页场景由 8 次任务查询减为 4 次。增加并发共享及快照隔离回归测试。
- 任务列表的负责人及活动选项并行读取；任务编辑页四项独立查询并行；报名页统计与活动详情并行。保留必须先执行的权限、有效性和错误判断。
- 本地前端重建为现有 Dockerfile 的 production target，运行 `node server.js`，消除逐页开发编译。只重建／替换 frontend，数据库容器与卷保持原状。
- 会议页旧测试的每页 8 条及已移除排序文案断言，与当前 10 条和排序选项对齐；不改会议功能。

会议、任务、活动详情已有部分并行查询，活动详情已用 Suspense 分离区域，列表已有分页及筛选节流。本轮保留这些机制。没有为纯展示页面添加无依据的 memo，也没有把参与者数据加入共享缓存。

## 日常使用与回退

项目日常使用运行 `./start-local.ps1 -Build`，默认 Production；源代码修改后必须重新构建才生效。只有继续开发时使用 `./start-local.ps1 -Mode Development -Build`，此模式仍保留当前 webpack 配置，会出现首次路由编译等待。切换模式不会重置数据库。

代码回退只撤销本轮权限去重、Dashboard 请求共享、页面并行查询与对应测试变更，然后重新构建前端。勿覆盖此前已有的工作区修改。

## 第二轮：多角色实测与大数据优化

使用本地生产容器、独立 Chromium、1440×1000 与 390×844 视口。测试使用本轮新建的 General、Secretary、Superuser、inactive 虚构账号及匿名会话，不修改已有账号。正常成员每条路由采样 3 次，匿名及停用会话采样 1 次；优化前后各 264 次，共 528 次导航。覆盖 24 个入口，包括首页、登录、后台入口、密码设置、Dashboard、会议列表／新建／详情、任务列表／新建／详情／编辑、活动列表／新建／详情／编辑、报名列表／详情、签到、晚餐列表／详情、Accounts、无效公开报名链接及旧入口。

两轮页面采样均未发生 HTTP 5xx 或浏览器未捕获异常，文档响应完成时间均小于 500 ms。此处文档响应从 navigation requestStart 到 responseEnd，包含流式响应完成；不等同于 FCP、LCP 或用户全部交互的时间。networkidle 仅作为自动化等待条件，不纳入文档响应时间。角色矩阵另外验证允许、拒绝、重定向，不能仅凭 HTTP 200 判断权限正确。

### 进一步优化

1. Dashboard 的 mine 从已授权的全体未完成任务快照过滤，不再单独读取相同任务；单页两种状态只需 2 次查询。增加其他负责人任务不会混入 mine 的回归测试。
2. Dashboard 折叠任务改为展开时渲染，Client Component 仅接收 id、title、dueDate、status；原来的数百条隐藏任务不再预先生成行。浏览器验证首屏 3 行、展开后 601 行、收起回到 3 行，单次展开交互约 95 ms。
3. 签到名单和活动任务候选的后续分页改为每批最多 4 页并行，保持页序、去重和失败关闭。新增并发上限及页序回归测试。
4. Accounts 页面处理与 layout 并行渲染时发生的 AuthorizationError，普通成员访问显示权限反馈，预期拒绝不再由页面查询抛出未处理异常。服务端授权和数据库 RLS 保留。
